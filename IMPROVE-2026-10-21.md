# Improvement Deep-Dive — NostrDanish/0xVector — 2026-10-21

Fork of VectorPrivacy/Vector (Tauri 2 + Rust + Android, default branch `master`, v0.4.4).

## Top recommendations (ranked, with effort S/M/L)

1. **[M] The `io.privacy0x` rebrand does not exist in the repo — commit it or drop the claim.**
   Verified this session: zero occurrences of `privacy0x` anywhere in the tree (code search + direct reads).
   - `src-tauri/tauri.conf.json`: `"identifier": "io.vectorapp"`, `"productName": "Vector"`
   - `src-tauri/gen/android/app/build.gradle.kts`: `namespace = "io.vectorapp"`, `applicationId = "io.vectorapp"`
   The repo *description* says "0xPrivacy fork of Vector" and claims `io.privacy0x`, but no manifest, gradle file, or config carries it. Decide: either land the rebrand (identifier + applicationId + namespace + productName + deep-link scheme/host + app data dirs `$DOWNLOAD/vector`, `$DOCUMENT/vector`) or fix the description. Note: changing applicationId/identifier changes the Android app identity and the updater/update paths — it is effectively a new app for installed users; plan migration.
2. **[S] Updater still points at upstream with upstream's signing key.** `tauri.conf.json` → `plugins.updater.endpoints` = `https://github.com/VectorPrivacy/Vector/releases/latest/download/latest.json`, and the minisign `pubkey` is upstream's. A fork build would offer *upstream's* signed releases as updates to fork users (and, once you ship your own signing key, silently break until then). Point endpoints at this repo's releases and generate your own minisign keypair, or disable the updater until you do.
3. **[S] Deep links still claim upstream's brand surface.** `deep-link` config registers scheme `vector://` and app-link host `vectorapp.io` (`/profile`, `/invite`, `/emojis`). The fork does not control `vectorapp.io`; claiming it in the manifest is both non-functional (no assetlinks.json on a domain you own) and a potential phishing vector. Rebrand to a host you control or remove the mobile host entries.
4. **[M] `glslc.exe` supply-chain hole in the Windows release build.** `.github/workflows/publish.yaml` downloads an executable from a personal server with no integrity check:
   `Invoke-WebRequest -Uri "https://jskitty.com/glslc.exe" -OutFile "glslc.exe"` → moved into vcpkg bin and executed. This binary compiles the whisper-rs Vulkan shaders that ship in every Windows release.
   Fix options (pick one):
   - Download the **official LunarG Vulkan SDK installer** (or `vcpkg install shaderc` which builds glslc from source) — removes the third-party binary entirely. The Linux job already installs `vulkan-sdk` from packages.lunarg.com; do the same class of thing on Windows.
   - If the custom binary is kept: pin an exact URL + verify a hardcoded SHA-256 (`(Get-FileHash glslc.exe).Hash -eq '<pinned>'`) and fail the build on mismatch. Host it in this repo's own release assets, not a personal domain.
5. **[S] zapstore.yaml / fastlane / README brand audit** — same pass as (1): any `vectorapp.io`, `VectorPrivacy`, or `vector` scheme references in store metadata still describe upstream.

## Missing gates (CI/tests/protection)

- CI exists (`tests.yaml`, `publish.yaml`, `fdroid-build.yaml`) — good. Gaps:
  - **No gitleaks/secret-scan workflow.** A committed keystore.properties or minisign private key would be catastrophic for a signing-identity project; add `gitleaks/gitleaks-action` (S).
  - **No branch protection on `master`** (verified: `protected: false` on every branch). Require PR + the tests workflow before merge (S).
  - **No `cargo audit` / Dependabot** for the Rust + npm surfaces — enable Dependabot for cargo/npm/github-actions (S).
  - The updater/pubkey/drift class of bug above would be caught by a CI check that greps `tauri.conf.json` for `VectorPrivacy` on PRs (S).
