# Security Audit — NostrDanish/0xVector — 2026-10-20

## Summary
Fork of VectorPrivacy/vector (Tauri 2 + Rust + Svelte Nostr E2EE messenger, "Vector"). The fork's `master` merged upstream `VectorPrivacy:master` on 2026-10-17 and contains upstream HEAD (2026-09-28, 20efc17), so it is fully in sync with upstream. The advertised "0xPrivacy / io.privacy0x" rebrand is NOT present on `master`: identifier and applicationId remain `io.vectorapp`, updater still pulls releases from the upstream repo, deep-links still use vectorapp.io. No committed secrets were found; signing is done via GitHub Actions secrets; keystores are gitignored. Main risks: an upstream-inherited supply-chain weakness in the Windows release pipeline (unverified exe download), upstream-bound updater identity, and upstream's design of exposing raw Nostr secret keys to the webview JS layer.

Findings: 0 CRITICAL / 1 HIGH / 2 MEDIUM / 1 LOW

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| VEC-01 | HIGH | .github/workflows/publish.yaml (Windows step) | Release pipeline downloads `glslc.exe` from a personal server (`https://jskitty.com/glslc.exe`) with no checksum/signature pinning and executes it while building signed release artifacts. Compromise of that host = code injection into signed releases. (Upstream-inherited.) | Fetch glslc from official Vulkan SDK release artifacts, or pin by SHA256 and verify before execution. |
| VEC-02 | MEDIUM | src-tauri/tauri.conf.json, zapstore.yaml, gen/android app/build.gradle.kts | Rebrand incomplete: updater endpoint points to `github.com/VectorPrivacy/Vector/releases/...` with upstream's minisign pubkey; deep-link host `vectorapp.io`; identifier/applicationId `io.vectorapp`; zapstore.yaml publishes from upstream repo. A "0xPrivacy" build would auto-update from upstream and is supply-chain-bound to upstream's signing key. | Either stay an explicit mirror (document it) or complete the rebrand: own updater endpoint + own minisign keypair, own identifier/applicationId, own deep-link host. Never mix: fork branding + upstream updater. |
| VEC-03 | MEDIUM | src-tauri/capabilities/default.json | Main-window capability grants include `allow-get-pkey`, `allow-set-pkey`, `allow-get-seed`, `allow-set-seed`, `allow-export-keys`: raw Nostr secret keys are exposed to the webview JS layer. Any XSS in the frontend = full identity theft. (Upstream-inherited design; CSP is tight which mitigates.) | Long-term: keep keys in Rust behind a signer-only command interface; never return raw key material to JS. Audit `src/` for XSS sinks (unsafe html rendering). |
| VEC-04 | LOW | gen/android app/build.gradle.kts, tauri.conf.json | Debug buildType enables cleartext traffic + JNI debuggable (dev-only); `macOSPrivateApi: true` and `withGlobalTauri: true` widen the desktop attack surface. | Keep debug flags out of release; review whether global Tauri injection is needed. |
